# `dot link` gets a second target mode: Seed Targets (copy-once), for app-owned config files

The symlink farm's defining property is that a linked file _is_ the repo file — same inode — so editing `~/.zshrc` is instantly a repo change with no sync step. That property inverts for a file the owning tool **rewrites at runtime**: Claude Code rewrites `~/.claude/settings.json` (model, `effortLevel`, theme, plugin toggles) on its own schedule, and because it's symlinked, every write dirties the repo tree. This is the churn behind the unresolved `git stash` conflict `/doctor` flagged as malformed JSON (#111) and the `config leak` warning `dot doctor` reports. #113/#114 resolved that one file ad-hoc by untracking it — which stopped the churn but discarded the cross-machine `enabledPlugins`/`theme` defaults deliberately landed in #78. A symlink is all-or-nothing: track it and eat the churn, or untrack it and lose the shared default. There was no middle.

Considered and rejected: a **wholesale switch to a chezmoi-style real-file model** (`apply` copies source → `$HOME`, `re-add` copies back). It would grant full churn immunity and templating, but at the cost of the instant-edit property on _every_ file — each `.zshrc` tweak would need an explicit `re-add`, and forgetting it (or forgetting `apply` after a source edit) is chezmoi's standing two-way-drift friction — to fix churn that only afflicts a handful of app-owned files. It is also a foundational rewrite of `classify_link`, the Manifest/undo, `dot restore`, backup, and doctor. **Adopting chezmoi outright** was likewise rejected: it discards the bespoke `dot` toolchain (git identity slots, `dot reconcile`, `dot doctor`).

Decided: a **hybrid**. Symlink stays the default, so author-owned files keep instant-edit unchanged. App-owned files opt into a copy-once **Seed Target** mode, declared by a `.seed` filename suffix — `home/.claude/settings.json.seed` seeds `~/.claude/settings.json` (suffix stripped). `managed_targets` recognizes the suffix by pattern and emits a per-target mode, so it stays the single source of truth with no hardcoded list, honoring "adding a target is just adding a file." Semantics mirror chezmoi's verified `create_` prefix: copy iff the target is **absent**; a present target is left untouched forever. Here that is **correctness, not convenience** — overwriting a present seed file would clobber exactly the app-managed runtime state the whole change exists to protect. A later edit to the `.seed` therefore does not propagate to machines that already seeded it; an explicit `dot link --reseed` (which backs up first) is the deliberate escape hatch for resetting to the shipped default. Because a present file means opposite things in the two modes, `classify_link` gains a `seeded` state: a real file at a Seed Target reads as success/leave-alone, not the `real` = "not ours, skipping" conflict a real file signals at a symlink target. The Manifest records an undo row for a seed only when `dot link` actually created the file, so `dot restore` removes a freshly-seeded file but never deletes pre-existing app state.

`settings.json` becomes the worked example, and a better outcome than the bare untrack: a tracked `home/.claude/settings.json.seed` carries the durable shared config (statusLine wiring, `enabledPlugins`, `theme`) while omitting the volatile `model`/`effortLevel`, and the live `~/.claude/settings.json` stays gitignored and app-owned. A fresh machine is seeded once and gets the defaults back; steady state has zero churn.

Status: accepted; implementation tracked in #115.
