# Detect config-dir leaks via `git status`, not custom scanning logic

`config/*`/`home/*` directories are symlinked from `$HOME` back into the repo's own working tree — `$HOME/.config/<pkg>/file` and `config/<pkg>/file` are the same location on disk. This means any tool that writes runtime/generated state into its own `$HOME/.config/<pkg>/` directory creates an untracked file directly inside the repo (as happened with git's `allowed_signers`, #58). Rather than building custom file-walking/comparison logic to detect this (the originally proposed approach), `dot doctor` runs `git status --porcelain --untracked-files=normal -- config/ home/` directly — git's own untracked-vs-ignored distinction is the detector, and the repo's existing `.gitignore` is the false-positive carve-out, for free. Modeled as its own direct check (like `check_identity_audit`) rather than forced into `reconcile_summary`'s declared-vs-actual domain loop, since a leak has no "missing" counterpart. Report-only, like the rest of `dot doctor` — `--strict` already exists to gate warnings when needed.
